# v3 — USB-paced reporting and longer calibration

Flash `DGB_ICM45686_calibration_DS4_1kHz_TEST_v3.uf2` using BOOT mode. Leave the unit stationary for at least two seconds after initialization. v1 and v2 remain available.

The 1 ms USB interrupt endpoint now paces report delivery directly. Firmware queues the next report whenever the previous transfer completes instead of also waiting on an independent 1000 us software timer. Independent USB/software clocks can miss polling opportunities. This is a potential cause of reduced delivery rates, not a measured diagnosis of the reported 600 Hz on your host.

A 1500 Hz software loop cannot make this full-speed 1 ms interrupt endpoint deliver 1500 reports/s. Sensor ODR remains 1600 Hz, already above the USB target; increasing it without evidence would not resolve host scheduling. Target remains approximately 1000 USB reports/s. Actual host delivery must be measured after flashing.

Stationary gyro calibration now requires a two-second window (previously one second), retaining at least 1000 fresh samples per initialized sensor. This gives more samples for offset averaging at the existing ODR. Motion rejection, fractional offsets, previous-good-bias retention, and live output on calibration failure remain. No continuous bias learner or extra deadzone is introduced.

Send `?` at 115200 USB serial to check calibration and queue statistics. If reporting stays near 600 Hz, record the measuring application's name and its result, plus two serial status snapshots several seconds apart. Firmware queue counts do not independently prove host arrival rate. Check with touch released and held.
